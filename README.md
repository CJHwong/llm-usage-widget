# Ollama Gauge

A macOS menu-bar app that scrapes Ollama, ChatGPT Codex, and Claude usage and shows it in two places: real Notification Center widgets and a floating desktop panel. It reuses your browser's existing login session, so there's nothing extra to authenticate.

The app is split in two:

- **Host app** (`Ollama Gauge.app`): unsandboxed menu-bar accessory. It scrapes every 5 minutes (Playwright/curl + browser cookies), writes `usage.json` into a shared App Group container, tells the widgets to reload, and optionally draws the floating desktop panel (transparent over the wallpaper, which a widget can't be). Its menu bar has **Show Desktop Panel**, **Enable ChatGPT**, **Enable Claude** toggles and a **Browser** source picker.
- **Widget extension** (`OllamaGaugeWidget.appex`): sandboxed WidgetKit extension. It reads that same App Group container and renders two widgets: **Ollama** (medium) and **Ollama + ChatGPT + Claude** (large). The host is unsandboxed and the widget is sandboxed, but both reach the group container, so there's one copy of the data and no mirroring.

ChatGPT and Claude share one Playwright pass. Each has its own menu-bar switch. When a switch is off (or you're not signed in), that provider's half of the large widget shows "ChatGPT off" / "Sign in to ChatGPT", and the desktop panel shows the same quiet state.

The header shows the newest successful read across all sources. If a fetch fails, a second line names the source ("Claude not updating") while the last good number stays on screen. After 15 minutes the card stops showing the number and says "Not updating" with the last read time and the reason.

## Tutorial: first run

Requirements:

- macOS 15+, Xcode 16+
- An Apple Development signing identity added under Xcode > Settings > Accounts (automatic signing registers the App Group; no portal visit needed)
- `xcodegen`: `brew install xcodegen`
- Zen or Firefox, signed into [ollama.com](https://ollama.com)

Build and install:

```bash
./build.sh
```

Generates the Xcode project, builds a signed `.app` with the embedded widget into `/Applications`, and registers a LaunchAgent that runs it at login. Then open Notification Center (or desktop edit mode) and add the **Ollama Gauge** widget.

## How-to guides

### Run it at login

`./build.sh` already installs the LaunchAgent. Logs from the scraper go through the unified logging system (`log show --predicate 'subsystem == "com.llmwidget"'`); LaunchAgent stdout/stderr go to `/tmp/llm-widget.log`.

Stop with `launchctl bootout gui/$(id -u)/com.llmwidget`. Restart with `launchctl kickstart -k gui/$(id -u)/com.llmwidget`.

Only one instance runs at a time (guarded by an `instance.lock` in the App Group container), so launching the app by hand while the LaunchAgent owns it is a no-op.

### Enable ChatGPT Codex or Claude usage

First install the scrape prerequisites:

```bash
playwright-cli install-browser firefox
```

Then toggle **Enable ChatGPT** or **Enable Claude** in the menu bar. Each switch gates the (expensive) browser scrape for that provider. Both providers share one Playwright launch, so turning either on runs the same pass. Turn a switch off the same way; the panel and widget update on the next scrape. If a switch is on but that site is not signed in, the large widget shows "Sign in to ChatGPT" or "Sign in to Claude".

Claude reads the `usage` response of the `claude.ai` settings page, and takes only the weekly (`weekly_all`) meter. The app retries once, keeps the last good number, and marks it "Not updating" after 15 minutes. The error distinguishes a failed page load, an unsuccessful response status, a missing response, and unreadable usage. A missing response does not confirm a block.

### If the widget does not appear in the gallery

The system (`chronod`) silently rejects widget extensions that are not properly sandboxed/entitled. If the widget is missing:

```bash
pluginkit -m -i com.hoss.ollama-gauge.widget     # should list it
pluginkit -a "/Applications/Ollama Gauge.app/Contents/PlugIns/OllamaGaugeWidget.appex"
log show --last 5m --predicate 'subsystem == "com.apple.chronod"' | grep -i ollama
```

Re-run `./build.sh` (which calls `pluginkit -a`) and re-login if it still won't register.

## Reference

### Project layout

```
LLMUsageWidget/
  project.yml            xcodegen spec: app + widget extension targets
  App/                   host app (unsandboxed): Scraper, AppPaths, BrowserAdapter, App entry
  Widget/                widget extension (sandboxed): TimelineProvider + widget views
  Shared/                Models + UsageDataStore (App Group bridge) + shared SwiftUI views
```

The `.xcodeproj` and `build/` output are generated by xcodegen/xcodebuild and gitignored.

### Browser support

- Zen
- Firefox
- Chrome

Firefox-family cookies are read straight from `cookies.sqlite`. Chrome cookies are AES-encrypted, so the host decrypts them with the "Chrome Safe Storage" key from the login Keychain (you approve the Keychain prompt once). Pick the source from the menu bar's **Browser** submenu; **Automatic** uses the first one found. You must be signed into the sites in the selected browser.

Safari, Arc, and Edge are **not** supported.

### Data directory: the App Group container

Everything lives in `~/Library/Group Containers/3GXP3XQ69M.com.hoss.ollama-gauge/`, shared by the host and the sandboxed widget:

- `usage.json`: last scraped payload, including a derived `chatgpt_status` (`on` / `off` / `unavailable`) the host computes for the widget
- `instance.lock`: single-instance flock

The ChatGPT and desktop-panel toggles live in the host's `UserDefaults`, not here, since the widget only needs the derived `chatgpt_status`.

### Preflight checks

The scraper logs any of these instead of producing data:

- no supported Zen/Firefox profile found
- missing `sqlite3` or `curl`
- ChatGPT enabled without `playwright-cli`
- ChatGPT enabled without the Playwright Firefox bundle

## Explanation: how it works

**Ollama:** reads session cookies from the browser profile and fetches `ollama.com/settings` with `curl`, then parses the usage meters out of the HTML.

**ChatGPT:** launches a Playwright Firefox session that reuses the browser's cookies, loads a ChatGPT settings page, and reads the `backend-api/wham/usage` response that page fetches. It reads the API's JSON, not rendered page text: OpenAI removed the Codex analytics page in Oct 2026, and the API survives UI redesigns.

Both run locally in the host app. The widget extension only reads the mirrored cache; it never scrapes. The only network traffic is the requests to ollama.com and chatgpt.com that your browser would make anyway.
